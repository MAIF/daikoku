# Domain Docs

This repo uses a single-context domain-doc layout.

Before exploring a domain area, read the root `GLOSSARY.md` if present and relevant decisions in `docs/adr/`. If either is absent, proceed silently; create them only when domain terms or decisions are resolved. Also read [`docs/DOMAIN.md`](../../DOMAIN.md), Daikoku’s existing domain overview.

Use glossary terms consistently in issues, hypotheses, tests, and proposals. If a needed term is missing, flag the gap rather than inventing a synonym. Surface conflicts with existing ADRs instead of silently overriding them.
